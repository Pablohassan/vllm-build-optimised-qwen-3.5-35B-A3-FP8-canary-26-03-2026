# Qwen3.5-35B-A3B-FP8 on 2x DGX Spark: promoted main-20260326 profile

This note summarizes the validated production-oriented profile used to promote a newer FP8 build over an older stable stack.

## Hardware and topology

- `2x DGX Spark / GB10 / SM121`
- `tensor_parallel_size=2`
- inter-node Ray / TP deployment

## Final retained profile

- `max_model_len=32768`
- `gpu_memory_utilization=0.33`
- `max_num_batched_tokens=8192`
- `max_num_seqs=32`
- `scheduling_policy=priority`
- `kv_cache_dtype=fp8`
- `tool_call_parser=qwen3_coder`

Environment knobs retained:
- `VLLM_TUNED_CONFIG_FOLDER=/workspace/deploy/tuned-configs`
- `VLLM_USE_RAY_COMPILED_DAG_CHANNEL_TYPE=shm`
- `VLLM_TEST_FORCE_FP8_MARLIN=1`
- `VLLM_MARLIN_USE_ATOMIC_ADD=0`

## Important runtime finding

On this build, forcing the Marlin FP8 path was necessary to avoid the failing `cutlass_scaled_mm` path on this hardware.

Observed selected kernel path:
- `MarlinFP8ScaledMMLinearKernel`

## Performance summary

Previous stable baseline:
- `tg256 = 60.53 ± 0.26 tok/s`
- `ttfr = 92.61 ± 3.95 ms`

Promoted main-20260326 baseline:
- `tg256 = 67.05 ± 0.10 tok/s`
- `ttfr = 83.48 ± 1.66 ms`

Concurrency results:
- `c24`: `404.49 ± 14.24 tok/s`, `ttfr = 562.92 ms`
- `c32`: `495.06 ± 4.80 tok/s`, `ttfr = 692.43 ms`
- `c40`: `515.18 ± 3.00 tok/s`, `ttfr = 877.05 ms`

Decision:
- `c40` gave the highest raw synthetic throughput
- `c32` was retained as the production cap because it provided a better latency / throughput balance

## Quality

Fixed prompt probes and concurrent smoke tests stayed clean on the promoted image.

Concurrent quality checks were validated at:
- `24`
- `32`
- `44`

No obvious degradation was observed on those smoke tests.
